# AGENTS.md

Короткая памятка для агента. Правила проекта: `CONSTITUTION.md`. Цель: `MANIFEST.md`. Прямая инструкция оператора в текущей задаче приоритетнее, кроме правил безопасности (секреты, приватность, деструктивные операции).

## Перед началом
1. Прочитать `MANIFEST.md`, `CONSTITUTION.md`, `PLAN.md` и нужный `specs/*.md`.
2. Если задач больше трёх или затрагивается схема БД, показать план задач и дождаться подтверждения.

## Команды
- Установка: `uv sync`
- Тесты: `uv run pytest -q`
- Линт и формат: `uv run ruff check .` и `uv run ruff format .`
- Проверка типов: `uv run mypy src` (тип-чекер: mypy)
- Запуск пайплайна: `uv run qa-pipeline --help` (точка входа в `[project.scripts]`, реализация `src/qa/cli.py`)
- Дашборд: `uv run qa-dashboard`

## Структура
- `src/qa/` код (`db/`, `pipeline/`, `llm/`, `vectors/`, `dashboard/`, `report/`, `settings.py`)
- `migrations/` миграции SQLite
- `prompts/` версионируемые промпты
- `schema/` кодбук и дерево тем (YAML), pydantic-модели
- `specs/` спецификации, `docs/` решения и идеи, `tests/` тесты
- `data/` и `.env` не коммитятся и не читаются в логи

## Жёсткие правила
- Только `uv`. Никаких `pip install` и глобальных установок.
- Секреты и эндпоинты только в окружении и `config.yaml`. Не писать в код и логи.
- Схема БД только через миграции. Деструктивные операции только с подтверждением.
- LLM только через `llm/`. Ответы по JSON-схеме. В тестах заглушка.
- Не трогать без разрешения: `MANIFEST.md`, `CONSTITUTION.md`, исходный кодбук, применённые миграции.
- Остановиться и спросить (шаблон STUCK) после трёх неудач с одной ошибкой, двух неудачных подходов или при выходе за рамки SPEC.
- Не ослаблять тесты ради зелёного результата.

## Завершение задачи
Отчёт: что сделано, как проверено, отличия от SPEC, открытые вопросы.
