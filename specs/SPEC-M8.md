# SPEC-M8: оркестрация и представление цитат

Статус: approved (решения оператора 2026-11-12, см. `docs/DECISIONS.md`)
Связь с MANIFEST: §2 (оператор запускает команду и получает результат), §6
(воспроизводимость, простота, прослеживаемость), §8.1 (первый транскрипт проходит
путь без ручного вмешательства в код), §8.2 (нет цитат, которых нет в тексте)

## Цель

Собрать отдельные стадии в одну идемпотентную команду `qa-pipeline run <код>`,
которая доводит интервью от расшифровки до дашборда и отчёта, останавливаясь на
воротах терминов (ворота качества сохранены, но по умолчанию выключены), и дать
отчёту читаемые цитаты с проверяемым происхождением (правка + оригинал с
тайм-кодом).

## В рамках / вне рамок

В рамках:

- команда `run` с воротами и флагами `--db`, `--dry-run`, `--skip-terms`;
- таблица терминов (xlsx) на интервью, её экспорт и импорт;
- представление цитат в отчёте: отбор, обрезка, необязательная правка моделью,
  показ оригинала с тайм-кодом;
- раздел отчёта «Ожидания и рекомендации респондентов»;
- подготовка отчёта к будущей агрегации нескольких интервью.

Вне рамок (в `docs/IDEAS.md`):

- анонимизация текста на загрузке (названия организаций и продуктов остаются
  в репликах) — отдельный мини-спринт;
- корпусной дашборд по нескольким интервью;
- нарратив модели по темам (текст, а не шаблон с числами);
- `structure --rebuild` на размеченном интервью (схема БД не меняется);
- кластеризация `new_term`.

## Контракты данных

### Схема БД

**Не меняется.** Миграции не добавляются.

Тайм-код реплики уже хранится: `turn.start_sec` (секунды от начала записи),
`utterance.turn_ids` — JSON-массив id записей. Тайм-код реплики = `MIN(start_sec)`
её записей; тайм-код фрагмента = тайм-код его реплики. Отдельного поля не нужно
(проверено на данных: 218 записей, диапазон 1–2373 с).

### Файлы

| Файл | Назначение | Коммитится |
|---|---|---|
| `data/exports/terms_<код>.xlsx` | таблица терминов на интервью | нет (`data/`) |
| `data/exports/quality_sample_<код>.xlsx` | выборка 10–15 реплик L1/L2 | нет |
| `data/exports/quote_edits_<код>.json` (вариант, см. вопрос 4) | разовые правки | нет |

### `run.params_json`

Новых ключей не требуется: стадия уже выводится из `params_json`
(`qa/db/analytics_repo.py::run_stage`). Команда `run` состояние не пишет.

## Поведение и правила

### A. Команда `qa-pipeline run <код>`

1. Идемпотентна. Состояние вычисляется из БД, отдельной таблицы статусов нет.
2. Выполняет **следующий возможный шаг** и останавливается, если шаг — ворота.
   Шаги по порядку, каждый проверяет своё условие готовности:

   | Шаг | Условие «уже сделано» | Что делает |
   |---|---|---|
   | 1. Книга | `codebook_version` не пуста | `load-codebook` |
   | 2. Проект | `interview` и `lexicon` заполнены | `load-project` |
   | 3. Интервью | `interview` по коду есть, роли записаны | `init-interview` + `load-transcript` |
   | 4. **Ворота 1: термины** | нет `new_term.status='proposed'` для интервью | экспорт таблицы и остановка |
   | 5. L2 | `text_unit` для интервью есть | `normalize` |
   | 6. Фрагменты | `fragment` для интервью есть | `structure` |
   | 7. Кодирование | `annotation` для интервью есть | `code` |
   | 8. **Ворота 2: качество** | `data/exports/quality_sample_<код>.xlsx` просмотрен (файл-маркер `data/exports/quality_sample_<код>.done`) | экспорт выборки и остановка |

   Ворота 2 выключены по умолчанию (`m8.quality_sample_enabled=false`): шаг 8
   пропускается, файл не создаётся, ограничение в отчёт не добавляется
   (см. «Уточнения при реализации», п. 6).
   | 9. Дашборд | файл `data/exports/dashboard_<код>.html` новее последнего `run` | `dashboard` |
   | 10. Отчёт | файл `data/reports/report_<код>.html` новее последнего `run` | `report` |

3. **Ворота 1 блокирует**: пока есть необработанные `proposed`, шаги 5–10 не
   выполняются. Незаполненные строки таблицы продолжение не блокируют: блокирует
   только наличие неразобранных кандидатов, а не их число. Пустая таблица (все
   строки просмотрены, часть оставлена без решения) считается пройденной.
4. **Ворота 2 не блокирует**: выборка выгружается, конвейер идёт дальше.
   Отсутствие файла-маркера не останавливает шаги 9–10, но в отчёте появляется
   ограничение «выборка качества не просмотрена». По умолчанию ворота
   выключены и не делают ни того, ни другого (см. «Уточнения при реализации»,
   п. 6).
5. Флаги:
   - `--db` — путь к БД (общий с остальными подкомандами);
   - `--dry-run` — печатает план шагов и что будет сделано, без записи;
   - `--skip-terms` — пройти ворота 1 без таблицы (кандидаты остаются
     `proposed`; в отчёт добавляется ограничение).
6. Код выхода: `0` — шаги выполнены или достигнуты ворота; `1` — ошибка стадии
   (сообщение как у соответствующей подкоманды).
7. Каждая стадия вызывается существующей функцией, а не копией логики: `run` —
   только выбор шага и печать. Прямых SQL в `run` нет (CONSTITUTION §4).

### B. Таблица терминов

**Экспорт** (`data/exports/terms_<код>.xlsx`, один файл на интервью):

- Источник — `new_term` интервью со статусом `proposed`, форма и частота.
  Частота считается по вхождениям в репликах респондента L1 (`suspect_frequencies`),
  а не по числу реплик.
- Колонки: `форма`, `частота`, `тайм-код`, `реплика_контекста`,
  `правильное_написание_или_смысл`, `комментарий`.
- `реплика_контекста` — 1–2 реплики вокруг вхождения, **только из
  анонимизированного текста** (`utterance.text`), **только из реплик с
  содержимым**: бэкканалы (`is_backchannel=1`) и реплики короче 4 слов не
  используются. Метки говорящих в таблицу не попадают: `turn.speaker_label`
  содержит настоящие имена и в выгрузку не идёт, показывается роль.
- Сортировка: по частоте убыванию, затем по алфавиту. Формы с одним вхождением
  — отдельным блоком ниже, с заголовком-разделителем.
- Шапка файла — инструкция коллегам: имена и организации не вписывать,
  использовать обозначение из таблицы имён; указывать тайм-код при
  прослушивании; пустая строка = решения нет.

**Импорт** (`qa-pipeline import-terms <код> [файл]`) — два вида правил:

1. «Всегда заменять X на Y» → `LexiconRepository.add_variant(Y, X)`,
   `source='review'` (как `review-terms`). Действует при следующей нормализации.
2. «В этой реплике имелось в виду Z» → разовая правка. **Требует решения
   оператора**: см. вопрос 4. Предлагаемый вариант без схемы — файл
   `data/exports/quote_edits_<код>.json` (`utterance_id`, `from`, `to`),
   применяемый как подсказка модели при нормализации, без перезаписи L1.

Правки применяются **до** нормализации: `run` импортирует таблицу на шаге 4,
`normalize` на шаге 5 уже видит пополненный лексикон. Заморозка L2 не нарушается:
уже записанная версия не перезаписывается, нужен `--new-version`.

### C. Представление цитат (слой отчёта; L1 и L2 не меняются)

1. **Отбор.** Из аннотаций темы исключаются фрагменты с
   `fragment.asr_quality='garbled'`; `doubtful` допускаются, но идут после `ok`
   и помечаются. Предпочтение: `asr_quality='ok'`, длина 80–400 символов,
   `annotation.reliability >= 2`, не `interpretation_only`.
2. **Обрезка** детерминированная: обрывок в начале/конце режется по границе
   слова, вырезка отмечается `[…]` (не `…`, чтобы отличать от авторского
   многоточия). Логика рядом с `aggregate.truncate_quote`, без модели.
3. **Правка моделью** — только для уже выбранных цитат, только если пп.1–2 не
   дали читаемости. Включается настройкой `m8.quote_edit_enabled`, по умолчанию
   `false`. Промпт `prompts/quote_edit.md`, вызов только через `llm/`, ответ по
   JSON-схеме. Автопроверки как в нормализации: сохранены числа и отрицания,
   язык тот же, доля изменений не выше порога, добавления только в `[квадратных
   скобках]`. Не прошедшая проверку правка отбрасывается, показывается оригинал.
4. **Показ.** Цитата в правке, под ней — оригинал с тайм-кодом и пометкой
   источника (`L2` + тайм-код; при `--show-l1` — текст L1). В начале блока
   цитат — строка: «Цитаты частично отредактированы: обрезка отмечена […],
   правка модели — по правилу <название>, оригинал приведён под каждой цитатой».

### D. Отчёт

1. **Синтез по темам** (расширение текущего блока цитат): частота темы
   (число аннотаций), 2–3 цитаты по правилам C, противоречия — пары аннотаций
   одной темы с разными кодами-полюсами (например, `A1` и `A2`), детерминированно.
2. **«Ожидания и рекомендации респондентов»** — отдельный раздел: аннотации,
   чьи коды отнесены к типу «ожидание/рекомендация», сгруппированные по темам.
   Нарратива модели нет: заголовки, число и цитаты.
3. Структура модели отчёта (`report/model.py`) получает поля так, чтобы
   несколько интервью агрегировались позже: список интервью вместо одного
   `provenance`, темы с ключом `(узел, тема)`; сейчас список из одного элемента.

**Тип кода.** В схеме есть `code.kind`, но во всех 84 строках он
`содержание`; атрибутов «ожидание/рекомендация/барьер» нет. Минимальный способ
без миграции — соответствие в `config.yaml`:

```yaml
m8:
  expectation_codes: ["C1", "C2", "C3", "C4"]   # пример, состав утверждает оператор
```

Список читается в `Settings`, попадает в `run.params_json` отчёта. Коды вне
списка в раздел не входят. Альтернатива — заполнить `kind` в листе «Коды»
(данные, не схема), но книга — исходный кодбук и без разрешения не меняется.

### E. Критерии приёмки

| № | Критерий | Команда проверки |
|---|---|---|
| 1 | `run` на уже обработанном R01 ничего не меняет и печатает «всё сделано» | `uv run qa-pipeline run R01 --db <копия>` дважды; второй запуск не создаёт `run`/`text_unit` |
| 2 | `run --dry-run` не пишет в БД | до/после: `SELECT COUNT(*) FROM run` |
| 3 | Ворота 1 останавливают конвейер при `proposed` | на копии: `run` → шаг 4, `text_unit` не растёт |
| 4 | `--skip-terms` проходит ворота 1 | `run --skip-terms` доходит до шага 10 |
| 5 | Таблица терминов: только анонимизированный текст, без меток и бэкканалов | тест: в ячейках нет `speaker_label`, нет `is_backchannel=1` |
| 6 | Импорт «X→Y» пополняет лексикон с `source='review'` | тест + `SELECT source FROM lexicon` |
| 7 | Цитаты: `garbled` не попадает, `doubtful` после `ok` и помечен | тест на синтетике |
| 8 | Обрезка ставит `[…]`, а не `…` | тест |
| 9 | Правка моделью выключена по умолчанию и не вызывается | тест: `m8.quote_edit_enabled=false` → 0 вызовов |
| 10 | У каждой цитаты есть тайм-код и оригинал | тест рендера |
| 11 | Раздел ожиданий строится только из кодов списка | тест |
| 12 | Числа отчёта совпадают с БД | существующий тест отчёта + новый |

## Риски и зависимости

- **Анонимизация неполная.** В `utterance.text` остаются названия организаций
  и продуктов (R01: брокер, приложение, «Кодекс»). `NAMES_MAP_PATH` в `.env`
  пуст. Формально таблица строится из анонимизированного текста, но для
  отправки коллегам нужен ручной просмотр или отдельный спринт (IDEAS).
- **`structure --rebuild` на размеченном интервью запрещён** (заморозка). Для
  R01 цепочка «пополнить лексикон → `--new-version` → пересборка» недоступна:
  `run` на R01 после новой версии L2 остановится на шаге 6 с понятным
  сообщением. Для R02 (с нуля) ограничение не действует.
- **Ворота 2 без эталона.** `golden_sample` пуст (0 строк), измерять не с чем.
  См. вопрос 3.
- **Дубли `new_term`.** 132 строки, 125 уникальных форм: таблица должна
  схлопывать повторы, иначе коллега увидит одну форму дважды.
- Новая зависимость не нужна: xlsx — `openpyxl`, уже используется.

## Проверка по конституции

- §4: схема только миграциями — миграций нет; SQL только в `db/`; `run` не
  содержит SQL.
- §5: реальные метки (`turn.speaker_label`) не попадают в выгрузки и отчёты;
  в таблицу идут роль и анонимизированный текст.
- §6: L1/L2 не меняются; правка цитаты — слой отчёта; модель предлагает,
  человек решает; числа только из БД.
- §7: LLM только через `llm/`, JSON-схема, кэш, лимит; правка цитат выключена
  по умолчанию.
- §9: тесты на каждую стадию, сквозной на синтетике; ослабление запрещено.
- §12: изменение схемы, новые зависимости, смена провайдера — только с
  разрешения; в SPEC их нет.

## Отступления от PLAN.md

PLAN.md описывает M0–M5; M6 и M7 появились как отдельные SPEC (ревью/отчёт и
глоссарий). M8 добавляет оркестрацию и представление цитат — сквозной слой над
стадиями, а не новую стадию анализа. Соответственно:

- M4/M5 не переоткрываются: `run` только вызывает существующие команды;
- правки отчёта (раздел ожиданий, цитаты с оригиналом) уточняют выход M5, не
  меняя методологию;
- новые решения записываются в `docs/DECISIONS.md` при реализации:
  состояние без таблицы статусов, ворота и их блокирующий характер, способ
  задания типа кода, формат разовых правок.

## Решения оператора по открытым вопросам (2026-11-12)

1. **Формат транскрипта.** Оставить табуляцию (три поля), парсер не меняется.
2. **Раздел «Ожидания и рекомендации» — два подраздела**, без объединения:
   - «Границы автономии ИИ» — коды из `m8.autonomy_codes = [C1, C2, C3, C4]`
     (R01: 29 аннотаций);
   - «Советы и условия согласия» — аннотации к вопросам `m8.advice_questions =
     [17, 18, 21, 22]` (R01: 16 аннотаций), без отбора по коду, с группировкой
     по теме или коду внутри подраздела.
   Аннотация может попасть в оба подраздела (R01: одна с `C4`); в отчёте
   указывается, что счётчики подразделов не суммируются. Оба списка — в
   `config.yaml`, не в коде. Группировка детерминированная, без нарратива модели.
3. **Ворота 2** — без `import-golden` и без ручного эталона L2. Выгрузка
   случайных 10–15 реплик (L1 и L2 рядом) с решениями «принято / исправлено /
   отклонено» по образцу `coding_review.py`; метрика — доля принятых без правок.
   Хранение решений — существующая схема (см. реализацию); при нехватке места
   без миграции остановиться по §12.
4. **Разовые правки** — JSON-файл в `data/` рядом с интервью, применяется на
   этапе L2 до модели; `utterance.text` (L1) не меняется (§4). Хеш файла
   пишется в `run.params_json`. Миграции нет.
5. **Организации** — перед первой выгрузкой таблицы для коллег оператор
   заполняет `NAMES_MAP_PATH` (данные, не код); `run` предупреждает, если путь
   пуст в момент выгрузки. Анонимизация кодом — отдельный мини-спринт после M8.
   `turn.speaker_label` в выгрузки не попадает (§5).
6. **Маркер «выборка просмотрена»** — файл `.done` рядом с выгрузкой, привязанный
   к её хешу: после новой выгрузки старый маркер не действует.

## Уточнения при реализации (2026-11-12)

Отступления от буквы SPEC, принятые по ходу и не меняющие контрактов:

1. **Шаг 8 не перевыгружает существующую выборку.** Если файл
   `quality_sample_<код>.xlsx` уже есть, шаг получает статус «пропущено —
   выборка ждёт просмотра». Иначе повторный `run` перезаписывал бы файл и
   обнулял маркер `.done` (хеш меняется), и просмотр оператора терялся бы
   на каждом запуске. Перевыгрузка — явная команда
   `export-quality-sample`.
2. **`m8.quote_min_chars`** (по умолчанию 80) — нижняя граница
   предпочтительной длины цитаты. В SPEC это число было зашито в отбор;
   вынесено в конфиг рядом с `m4.quote_max_chars`, чтобы длину можно было
   менять без правки кода.
3. **`QuotePolicy` в модели отчёта.** Число обрезок, число правок и названия
   правил собираются в один объект, из которого рендер строит строку о
   происхождении цитат. Так отчёт не может утверждать, что правка была,
   когда она выключена.
4. **`qa/report/limitations.py::pipeline_limitations`.** Ограничения по
   состоянию конвейера (неразобранные термины, неприсмотренная выборка,
   применённые правки, пустая таблица имён) вынесены из `build_report` в
   отдельный модуль: они читают состояние через `PipelineRepository`, а
   модель отчёта остаётся без SQL.
5. **`interviews: tuple[Provenance, ...]`** вместо поля `provenance`; одиночное
   значение доступно свойством `provenance`. Так агрегация нескольких
   интервью не потребует менять рендер.
6. **Ворота 2 выключены настройкой `m8.quality_sample_enabled` (по умолчанию
   `false`).** Решение 3 предполагало сверку L2 с L1 и метрику «доля принятых
   без правок». Основание отмены — не результат прогона на R01, а понимание,
   что постановка бессмысленна: L2 не исправляет ошибки распознавания, он
   убирает заикания, повторы и мусорные звуки и приводит термины к лексикону,
   а опечатки ASR остаются опечатками в обоих слоях. Сверять в такой проверке
   нечего, поэтому выключенные ворота не создают файл, который никто не
   откроет, и не добавляют в отчёт строку «не подтверждено». Пробный прогон
   подтолкнул к этой мысли, но доказательством не был: на другом интервью
   вывод тот же. Код ворот сохранён целиком: `quality_sample_enabled: true`
   возвращает прежнее поведение (выгрузку, маркер и ограничение).
