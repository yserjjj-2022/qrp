# Анализатор интервью

Тематический анализ расшифровок интервью: транскрипт, размеченные фрагменты,
дерево тем с насыщением, отчёт. Цель и границы — `MANIFEST.md`, правила работы —
`CONSTITUTION.md`, этапы — `PLAN.md`.

## Установка

```bash
uv sync
```

Менеджер зависимостей только `uv`. Виртуальное окружение — `.venv` в корне, не коммитится.

|---|---|

| Команда | Назначение |
|---|---|

| `init-interview <R01.txt> --group "Не торгующие"` | Определить роли по числу слов и записать интервью |
| `load-transcript <R01.txt> [--interview-id] [--group]` | Разобрать транскрипт, псевдонимизировать, собрать реплики |

| `normalize <R01> [--dry-run] [--new-version] [--review-export]` | Нормализовать реплики интервью в слой L2 |
| `llm-ping [--normalize] [--dry-run]` | Проверить LLM-эндпоинт на синтетическом запросе |

### LLM-провайдер

`LLM_PROVIDER` принимает два значения:

| Значение | Поведение |
|---|---|
| `stub` (по умолчанию) | Заглушка, сетевых вызовов нет |
| `openai_compatible` | HTTP-вызовы к OpenAI-совместимому эндпоинту на стандартной библиотеке |

Для `openai_compatible` обязательны `LLM_ENDPOINT`, `LLM_MODEL` и `LLM_API_KEY`
(ключ только в `.env`). `LLM_MODEL_NORMALIZE` используется с флагом `--normalize`.
`LLM_CACHE_DIR` задаёт каталог кэша, `LLM_MAX_CALLS_PER_RUN` — лимит вызовов за прогон.
Попадание в кэш лимит не расходует.

`qa-pipeline llm-ping` отправляет один синтетический запрос (реальные данные не уходят)
и печатает фактическую модель из ответа (`model_used`), токены и время. С `--dry-run`
команда показывает объём вызова и ничего не отправляет.

### Нормализация (слой L2)

`normalize <R01>` читает реплики интервью из слоя L1 и записывает результат в L2.
Детерминированный проход (без модели) делает следующее:

- заменяет точные искажения из «Лексикона» канонической формой;
- нечётко сопоставляет неизвестные словарю слова с лексиконом (`rapidfuzz`);
  слова, которые знает `pymorphy3`, не трогаются — это обычная лексика, а не искажение ASR;
- склеивает пару соседних слов, если вместе они дают термин («ре балансланировка» →
  «ребалансировка»); склейка помечается в журнале `glued=true`;
- удаляет звуки-паразиты, схлопывает механические повторы, правит пробелы и пунктуацию.

Реплики респондента длиннее `m1b.min_words_for_model` (по умолчанию 4 слова) уходят в модель.
Реплики интервьюера, наблюдателя и бэкканалы в модель не уходят: у интервьюера формулировка
нужна как есть.

В промпт передаются предшествующая реплика интервьюера, лексикон, маркеры неуверенности,
строка предметной области (`domain_hint` в `config.yaml`) и список подозрительных слов —
тех, которых нет ни в словаре, ни в лексиконе. Только такие слова модель может исправить
по контексту через `asr_fix`; исправление обычного слова отклоняется автопроверкой.

Вывод модели принимается только после автопроверок: числа, отрицания, маркеры
неуверенности, латиница, `asr_fix`, потеря мысли и новые смысловые слова. Потеря мысли
сравнивается по лемам, поэтому смена словоформы не считается удалением; удалять можно
только паразитов из списка, механические повторы и слова, заявленные в `changes`.
При расхождении единица получает `status=rejected`, а в L2 остаётся детерминированный
результат; предложенный моделью текст сохраняется в `changes_json` (`type=model_output`)
для разбора. Результат пишется одной транзакцией вместе с записью `run`.

Перед первым прогоном лист «Лексикон» должен содержать термины проекта: без него
нечёткое сопоставление и проверки не смогут отличить термин от искажения.
После правки листа выполняется `load-project`.

| Флаг | Поведение |
|---|---|
| без флагов | Записать L2 версии 1; если версия уже есть — ничего не делать |
| `--new-version` | Записать следующую версию L2, старые сохраняются |
| `--review-export` | Выгрузить `data/exports/normalize_review_<R01>_v<версия>.xlsx`: все единицы с флагами (`names_review`, `asr_fix`, `doubtful`, `garbled`) плюс 15 случайных, колонки `L1`, `L2`, `changes` |
| `--dry-run` | Показать число реплик, вызовов модели и оценку токенов, ничего не отправляя |

### Кандидаты новых терминов (`new_term`)

Реплики, где модель встретила незнакомое слово, попадают в `new_term`. Разбор —
`qa-pipeline review-terms`, решение вводится одной строкой:

| Ввод | Действие |
|---|---|
| `y Термин` | Форма добавляется вариантом существующего термина (основной способ) |
| `y` | Форма принимается отдельным термином; второй вопрос спрашивает канон |
| `n` | Кандидат отклоняется, лексикон не меняется |
| `skip` | Кандидат остаётся без решения |

Вариант, добавленный так, получает `source='review'` и не перезаписывается
`load-project`. Замена выполняется детерминированным проходом, поэтому работает
сразу после `normalize` и не зависит от модели.

Роли говорящих правит оператор в листе «Роли_говорящих» (`id_интервью`, `метка_говорящего`,
`роль`, `слов`). После правки запускается `load-project`: роль доводится до `turn` и `utterance`,
реплики пересобираются. Правка листа не требует повторного `load-codebook` — версия книги
ищется по хешу кодбуковых листов. Пересборка останавливается, если на реплики уже ссылаются
кандидаты `new_term`.

Значения групп и их алиасы задаются в `config.yaml` (секция `groups`); статусы лексикона —
в секции `lexicon_status_map`. Схема листов рабочей книги (лист -> колонка -> тип) —
в секции `workbook`.

## Структура данных

Каталог `data/` не коммитится (`.gitignore`) и не попадает в логи.

```
data/
  inputs/                     входные файлы
    Rabochaya_kniga_proekta_v4.xlsx   рабочая книга проекта (путь: paths.workbook)
    transcripts/              транскрипты, имя файла = код респондента (R01.txt)
  db/interviews.db            SQLite (путь: paths.db)
  backups/                    копии БД перед миграцией
  cache/                      кэш LLM
  exports/                    выгрузки
  golden/golden_sample.xlsx   золотой набор для ручного L2
```

Пути задаются в `config.yaml` (`paths:`) и создаются автоматически при запуске команд.
Таблица «имя -> код» хранится вне репозитория, путь — переменная окружения `NAMES_MAP_PATH`.
Секреты — только в `.env` (образец: `.env.example`).

## Данные и приватность

- Имена заменяются кодами в тексте при загрузке; таблица соответствия не коммитится.
- Колонки `turn.speaker_label` и `interview_speaker.speaker_label` содержат настоящие метки
  говорящих. Это служебные данные локальной БД: они не выводятся в логи, отчёты и тексты
  L1/L2 и не передаются во внешние сервисы. Транскрипты L0 и рабочая книга с заполненным
  листом «Роли_говорящих» тоже не загружаются наружу (CONSTITUTION §5).
- Тексты реплик не пишутся в логи — только идентификаторы, размеры и хеши.
- Реплики с признаком `pii_flag` (телефон, e-mail, длинные числа) помечаются для ручной
  проверки, но не блокируют загрузку; ложные срабатывания на денежных суммах ожидаемы.
