# SPEC-M0: каркас проекта

Статус: approved
Связь с MANIFEST: разделы 4, 5, 6 (источники истины, выходы, заменяемость).

## Цель
Подготовить воспроизводимый каркас, в который затем добавляются стадии пайплайна. Транскрипты на этом этапе не нужны.

## Контекст и входы
- Приложение Б (Excel, структура зафиксирована): листы `Вопросы_и_коды`, `Коды`, `Атрибуты`, `Эталон_Финам`, `Было_стало`, `Словарь_замен`.
- Приложение А (Word): правила разметки (для справки, в код не загружаются).
- Настройки LLM и эндпоинтов задаются через переменные окружения (`.env`) и `config.yaml`. Секреты (ключи, токены) — только в `.env`.
- Прокси-маршруты задаются через `LLM_API_KEY` и `llm.endpoint` в настройках. Модели задаются через `llm.model` в настройках. Реальных значений в коде нет — только в `config.yaml`/`.env`.

## В рамках
1. Репозиторий по структуре из `AGENTS.md`: `pyproject.toml`, `.python-version`, `uv.lock`, `.gitignore`, `.env.example`, `config.yaml`, pre-commit. CLI оформлен как `src/qa/cli.py` с точкой входа в `[project.scripts]`.
2. Модуль настроек (`settings.py`): валидация, загрузка из `config.yaml` + `.env`. Обязательные поля: `db_path`, `llm.provider` (по умолчанию `"stub"`). С умолчаниями `None`: `llm.model`, `llm.endpoint`. Остальные умолчания: `data_dir`, `log_level`, `llm.max_calls_per_run`, `llm.cache_dir`, `vectors.backend`, `embedding.model`. Секрет `LLM_API_KEY` обязателен только если `llm.provider != "stub"`.
3. SQLite: подключение с `PRAGMA foreign_keys=ON`, `journal_mode=WAL`. Система миграций в `migrations/`. Миграция `0001` создаёт 15 таблиц: `interview`, `turn`, `fragment`, `codebook_version`, `code`, `attribute`, `question`, `annotation`, `review`, `run`, `theme`, `theme_code`, `embedding`, `code_proposal`, `theme_proposal`. Перед каждой миграцией — автоматическая копия БД в `data/backups/` с меткой времени (если файл существует и не пуст).
4. Загрузчик кодбука из приложения Б: читает листы `Коды`, `Вопросы_и_коды`, `Атрибуты`. Записывает `codebook_version` с хешем файла. Повторная загрузка того же файла не создаёт дублей.
5. YAML-шаблон дерева тем (`schema/themes.yaml` — пометка `draft`): два узла (риски, ответственность), темы по семьям кодов. Каждый базовый код привязан ровно к одной теме или помечен «без темы». Загрузчик дерева в таблицы `theme` и `theme_code`.
6. Интерфейсы `llm/` (`complete_json`, `embed`) и `vectors/` (`add`, `search`) с заглушками и конфигурацией провайдера. Прямых вызовов SDK вне `llm/` нет.
7. CLI-каркас `qa-pipeline` (подкоманда `load-codebook`, аргумент — путь к файлу кодбука).
8. Тесты и локальная проверка (ruff, mypy, pytest).
9. Документация: `docs/DATA_MODEL.md` (краткое описание 15 таблиц и полей), `docs/DECISIONS.md` (записи решений), `docs/IDEAS.md` (пустой).
10. Шаблоны: `specs/_TEMPLATE.md` (SPEC), `docs/templates/STUCK.md`, `docs/templates/DECISION.md`.
11. Минимальная настройка `logging` с идентификатором прогона (run_id).

## Зависимости

| Зависимость | Зачем | Чем заменить нельзя | Лицензия |
|---|---|---|---|
| `openpyxl` | Чтение Excel-файлов (Приложение Б) | Стандартная библиотека не читает `.xlsx` | BSD-3 |
| `pyyaml` | Чтение YAML-дерева тем | Можно было бы `json`, но YAML — стандарт для дерева тем в проекте | BSD-3 |
| `pydantic` | Валидация данных, pydantic-модели кодбука | Самодельная валидация — риск ошибок и нарушение CONSTITUTION | MIT |
| `pydantic-settings` | Загрузка настроек из `config.yaml` + `.env` | Самодельный загрузчик — дублирование, нарушение единого модуля настроек | MIT |
| `pre-commit` | Хуки: ruff, проверка секретов, размер файлов | `git hooks` вручную — легко забыть, нарушение CONSTITUTION | MIT |
| `pytest` | Юнит- и сквозные тесты | Самодельная `unittest`-обёртка — нет фикстур, маркеров, конвенций | MIT |
| `ruff` | Линт и форматирование | PEP8 через `flake8` медленнее, нет форматтера в одном пакете | MIT |
| `mypy` | Проверка типов | `pyright` — альтернатива, выбран mypy (решение оператора) | MIT |

## Вне рамок
Разбор транскриптов, вызовы реальной модели, эмбеддинги на реальных данных, дашборд, отчёт.

## Контракты данных
- `code`: id, family, name, definition, include, exclude, tiebreak, applies_to, codebook_version_id, origin (base|inductive), status (active|merged|retired), supersedes_id.
- `codebook_version`: id, file_hash, extensions_hash.
- `annotation`: id, fragment_id, code_id, source (llm|human), run_id, confidence, rationale, quote, quote_start, quote_end, status (proposed|accepted|edited|rejected).
- `run`: id, started_at, model, prompt_hash, codebook_version_id, code_version, params_json.
- `code_proposal`: id, code_name, definition, reason, status, run_id.
- `theme_proposal`: id, theme_name, reason, status, run_id.
- Подробные поля фиксируются в миграции 0001 и описываются в `docs/DATA_MODEL.md`.

## Критерии приёмки
1. `uv sync && uv run pytest -q` проходит на чистом клонировании без сети.
2. `uv run qa-pipeline load-codebook <файл>` загружает 42 кода и атрибуты (на Приложении Б); повторный запуск не создаёт дублей.
3. Миграции применяются к пустой БД и создают все 15 таблиц; повторное применение безопасно; копия БД сохраняется в `data/backups/`.
4. Заглушка LLM возвращает данные по схеме; прямых вызовов SDK вне `llm/` нет (проверка тестом или линтером).
5. В репозитории нет секретов; `.env.example` содержит только имена переменных.
6. Ruff и mypy без предупреждений.

## Тесты
- Загрузка кодбука: синтетический Excel (малое число кодов, проверка логики парсера) и тест с маркером `real_codebook` на настоящем Приложении Б (запускается только если задана переменная окружения с путём к файлу, ожидает ровно 42 кода, иначе пропускается).
- Миграции, настройки, интерфейсы-заглушки.
- Дерево тем: покрытие базовых кодов темами (каждый код привязан ровно к одной теме или помечен «без темы»).

## Риски и зависимости
Структура приложения Б зафиксирована, парсер должен падать с понятной ошибкой, если лист или колонка отсутствуют.

## Проверка по конституции
Критичны разделы 2 (uv, окружение, зависимости), 3 (секреты), 4 (миграции, резервная копия), 6 (индуктивные расширения), 7 (интерфейс LLM).
