# SPEC-M7b: нормализация ASR с подсказками оператору и памятью решений

Статус: approved (2026-11-18)
Связь с MANIFEST: §4 (рабочая книга и справочники — источник терминов), §6
(воспроизводимость, простота, прослеживаемость), §8.1 (первый транскрипт проходит
путь без правок в коде), §8.2 (нет цитат, которых нет в тексте)

## Цель

Заменить ручную очередь кандидатов терминов на память решений. Система сама
находит в расшифровке слова, которых нет в словаре и лексиконе, предлагает
варианты по созвучию и по смыслу, один раз спрашивает оператора и запоминает
ответ. На следующих интервью известные формы применяются кодом без модели и без
вопросов.

Метрик, версий конфигурации и подсчёта времени оператора в этой задаче нет. Слой
L1 не меняется.

## Контекст и входы

Состояние на 2026-11-18 (после T0, ветка `spec-T0/drop-golden`):

- нормализация L2 (`pipeline/normalize_l2.py`) делает детерминированный проход,
  затем вызов модели по каждой реплике респондента; в промпт подставляется
  отфильтрованный лексикон (M7), поэтому пополнение глоссария меняет ключ кэша;
- ворота «термины» (`orchestrate.py`, шаг 4) останавливают `run`, пока в
  `new_term` есть `proposed`; решения принимаются командой `review-terms` и
  пишутся в `lexicon` (`source='review'`);
- `lexicon.source` имеет `CHECK (source IN ('workbook','review'))`, поэтому
  `source='auto'` без миграции невозможен (см. «Контракты данных»);
- существующие функции переиспользуются: `suspect_words`, `is_known_word`,
  `lexicon_forms`, `apply_lexicon`, `apply_glue`, `apply_fuzzy_lexicon`,
  `normalize_deterministic`, `run_checks_detailed`, `load_lexicon`,
  `LexiconRepository`, `PipelineRepository`;
- `pymorphy3` и `rapidfuzz` уже в зависимостях: новых зависимостей задача не
  требует.

Отменённое решение, которое здесь фиксируется: «созвучно — значит то же самое»
(нечёткая замена по расстоянию без подтверждения моделью или оператором).
Причина отказа: на коротких и на латинских терминах созвучие даёт ложные
замены, а цена ошибки — искажённая цитата в отчёте.

## В рамках / вне рамок

В рамках:
- поиск подозрительных слов: нет в `pymorphy3`, нет в лексиконе, плюс места,
  которые модель по контексту считает нечитаемыми;
- применение известных форм из лексикона кодом (включая решения «оставить» и
  «неразборчиво»);
- подсказки по созвучию (код): общее фонетическое пространство, кириллические
  формы латинских канонов, `rapidfuzz`, склейка и разделение соседних слов;
- подсказки по смыслу (модель, `prompts/normalize_pick.md`, N выборок);
- автопроверки на уровне отдельной правки;
- таблица `data/exports/terms_<проект>.xlsx` с листами «Нужна помощь» и
  «Применено само»; команда `apply-terms`;
- удаление ворот терминов, шага `terms_table`, `manual_edits`, `quality_sample`
  и `review-terms` из пути по умолчанию команды `run`;
- `prompts/normalize.md` — только чистка речи;
- подпись отчёта о машинной расшифровке (текст согласуется, см. «Открытые
  вопросы»).

Вне рамок:
- кодирование, дашборд, отчёт (кроме подписи);
- кластеризация OTH, эмбеддинги, `vectors/`;
- изменение схемы БД сверх одной миграции на `source='auto'` (текст ниже,
  требуется разрешение);
- версионирование лексикона и перепрогон прошлых интервью;
- сравнение моделей и выбор провайдера (провайдер не меняется);
- новые зависимости.

## Контракты данных (таблицы, схемы JSON, форматы файлов)

### Миграция `0009_lexicon_source_auto.sql` — ТРЕБУЕТ РАЗРЕШЕНИЯ

Ничего не применяется до ответа оператора. Текст:

```sql
-- 0009: разрешить source='auto' в лексиконе (M7b).
-- Решения, принятые кодом без оператора, помечаются source='auto'.
-- Приоритет при конфликте: review > auto > workbook.
-- Статусы памяти (колонка status, CHECK не накладывается):
--   review | auto | keep («оставить») | unreadable («[неразборчиво]»).
PRAGMA foreign_keys=OFF;

CREATE TABLE lexicon_new (
    id INTEGER PRIMARY KEY,
    canonical TEXT NOT NULL,
    variants_json TEXT NOT NULL DEFAULT '[]',
    definition TEXT,
    status TEXT NOT NULL DEFAULT 'proposed',
    source TEXT NOT NULL DEFAULT 'workbook' CHECK (source IN ('workbook', 'review', 'auto')),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(canonical)
);

INSERT INTO lexicon_new (id, canonical, variants_json, definition, status, source, updated_at)
SELECT id, canonical, variants_json, definition, status, source, updated_at FROM lexicon;

-- Строк до и после переноса должно быть одинаково.
DROP TABLE IF EXISTS _guard_copy;
CREATE TABLE _guard_copy (n INTEGER NOT NULL CHECK (n = 0));
INSERT INTO _guard_copy
SELECT (SELECT COUNT(*) FROM lexicon) - (SELECT COUNT(*) FROM lexicon_new);
DROP TABLE _guard_copy;

DROP TABLE lexicon;
ALTER TABLE lexicon_new RENAME TO lexicon;

DROP TABLE IF EXISTS _guard_fk;
CREATE TABLE _guard_fk (n INTEGER NOT NULL CHECK (n = 0));
INSERT INTO _guard_fk SELECT COUNT(*) FROM pragma_foreign_key_check;
DROP TABLE _guard_fk;

PRAGMA foreign_keys=ON;
```

Альтернатива без миграции, если оператор откажет: писать автозамены с
`source='review'` и `status='auto'`. Тогда `source` перестаёт означать «кто
принял», приоритет вычисляется по `status`. Вариант хуже по читаемости и
противоречит §2.4 задания, поэтому предлагается миграция.

### Семантика `lexicon`

| Поле | Значение |
|---|---|
| `canonical` | целевая форма; для `keep` и `unreadable` — сама форма |
| `variants_json` | включает исходную форму, встреченную в ASR |
| `status` | `review`, `auto`, `keep`, `unreadable` (плюс прежние `proposed`/`approved`/`rejected`) |
| `source` | `workbook`, `review`, `auto` |

Правила чтения (`load_lexicon`):
- `rejected` — пропускается (как сейчас);
- `keep` — форма считается известной, замены нет, вопрос оператору не задаётся;
- `unreadable` — форма заменяется на `[неразборчиво]`;
- `review`/`auto` — обычная замена варианта на канон;
- при конфликте одной формы в двух записях выигрывает `review`, затем `auto`,
  затем `workbook`; проигравшая пара не применяется и попадает в таблицу как
  конфликт.

`load-project` не перезаписывает строки с `source='review'` и `source='auto'`
(сейчас так же защищён только `review`).

### Записи в `text_unit.changes_json` (журнал правок)

Существующие типы (`term`, `asr_fix`, `names_review`, `soft_thought_loss`,
`rejected`, `model_output`, `manual_edit`) сохраняются. Добавляются:

```json
{
  "type": "hint",
  "from": "сенжин",
  "position": 412,
  "hints": [
    {"to": "OsEngine", "confidence": 0.89, "source": "phonetic"},
    {"to": "keep", "confidence": 0.11, "source": "code"}
  ],
  "verdict": "candidate",
  "candidate": 0
}
```

```json
{
  "type": "decision",
  "from": "сенжин",
  "to": "OsEngine",
  "position": 412,
  "accepted": "review",
  "confidence": 1.0,
  "hint_rank": 1,
  "corrected_word": true
}
```

`position` — смещение в итоговом тексте L2 (в символах). `corrected_word: true` —
пометка «исправленное слово»: отчёт показывает под цитатой исходную форму.
`accepted` — `review` или `auto`; `auto` ставится, когда решение взято из
памяти (`source='auto'`) или применено по умолчанию из пустой ячейки.

### Таблица `data/exports/terms_<проект>.xlsx`

Один файл на проект, дополняется по мере интервью. Имя проекта —
`m7b.project_name` из `config.yaml`.

Лист «Нужна помощь» (по одной строке на форму, только новые формы; строки
дописываются, заполненные ячейки не перезаписываются):

| Колонка | Содержимое |
|---|---|
| `Форма` | как в L2 |
| `Где встречается` | `<код>: 00:12:31, 00:18:04` |
| `Контекст` | одна реплика, ≤ 200 символов, слово выделено |
| `Подсказки` | до 5: `OsEngine (0.89)`, `оставить (0.11)`, `[неразборчиво] (0.00)` |
| `ЗАМЕНА` | ввод оператора: пусто / `=` / `?` / текст |
| `Пояснение` | почему спросили: нет в словаре; созвучно; конфликт |

Лист «Применено само»:

| Колонка | Содержимое |
|---|---|
| `Форма` | как было в L1 |
| `Замена` | канон, `оставить`, `[неразборчиво]` |
| `Основание` | `лексикон: review`, `лексикон: auto`, `подсказка 0.89 (порог 0.67)` |
| `Где встречается` | как выше |

Правила колонки `ЗАМЕНА` (применяются в `apply-terms`):

| Значение | Решение |
|---|---|
| пусто | принять первую подсказку, если её уверенность ≥ `m7b.hint_confidence_threshold`, иначе «оставить»; `source='auto'` |
| `=` | оставить как есть (`status='keep'`, `source='review'`) |
| `?` | `[неразборчиво]` (`status='unreadable'`, `source='review'`) |
| текст | подставить текст (`status='review'`, `source='review'`) |

Сортировка листа «Нужна помощь» — по частоте формы в проекте (по убыванию), при
равенстве — по алфавиту.

### `config.yaml` — новая секция `m7b`

```yaml
m7b:
  project_name: qrp            # имя файла terms_<проект>.xlsx
  hint_samples: 3              # выборок на слово
  hint_temperature: 0.7        # температура выборок подсказок
  hint_seed: 0                 # базовое зерно; выборка i получает seed+i
  hint_confidence_threshold: 0.67
  hint_max: 5                  # максимум подсказок в таблице
  context_utterances: 3        # ±3 реплики вокруг слова
  memory_neighbours: 5         # прошлых решений оператора в промпте
  phonetic_threshold: 0.55
  phonetic_short_threshold: 0.70
  phonetic_short_length: 5
  auto_apply_defaults: true    # пустая ячейка применяет первую подсказку
  manual_edits_enabled: false  # разовые правки вне пути по умолчанию
  wait_on_terms: true          # остановка run перед сегментацией
```

`Settings` получает `M7bSettings` с теми же полями и валидацией диапазонов
(пороги 0–1, счётчики ≥ 1). Секция `m1b` не меняется.

## Поведение и правила (включая граничные случаи)

### Порядок стадий нормализации (предложение)

1. **Чистка речи** (`normalize_rules`): звуки, заикания, повторы, пунктуация.
   Не меняется.
2. **Память лексикона** (код, без модели): точные варианты, `keep`,
   `unreadable`, `review`/`auto`. Каждая замена проверяется автопроверками и
   пишется в `changes_json` как `decision`.
3. **Подозрительные слова**: `suspect_words` по тексту после шага 2 плюс слова
   из `uncertain_spans`, которые модель пометила как нечитаемые (шаг 4), если их
   нет в `pymorphy3` и в лексиконе.
4. **Холодный проход модели** (`prompts/normalize.md`, T=0, кэш): чистка речи,
   `asr_quality`, `uncertain_spans`. Терминов модель больше не подставляет,
   лексикон в промпт не подставляется — ключ кэша перестаёт зависеть от
   глоссария (снимает ретроактивность M7).
5. **Подсказки по созвучию** (код): фонетические кандидаты из лексикона и
   частых слов, склейка/разделение соседних слов.
6. **Подсказки по смыслу** (модель, `normalize_pick.md`): N выборок на слово,
   уверенность = доля выборок за вариант.
7. **Автопроверки**: правка применяется, только если проходит проверки; провал
   отменяет только эту правку.
8. **Таблица**: строки для форм без решения; лист «Применено само»; строка
   `слов для оператора: N`.

Порядок важен: шаг 4 выполняется до поиска подозрительных слов, потому что его
`uncertain_spans` расширяют список. Практически это один проход по репликам:
модель уже вызывается для чистки, отдельного вызова «найди нечитаемое» нет.

### Фонетические подсказки (детерминированно)

`phonetic_key(word)`:
1. нижний регистр, `ё`→`е`, удалить всё кроме `а-я` и пробелов;
2. латиница → кириллица по таблице: `a`→а, `b`→б, `c`→к, `d`→д, `e`→е, `f`→ф,
   `g`→г, `h`→х, `i`→и, `j`→дж, `k`→к, `l`→л, `m`→м, `n`→н, `o`→о, `p`→п,
   `q`→к, `r`→р, `s`→с, `t`→т, `u`→у, `v`→в, `w`→в, `x`→кс, `y`→и, `z`→з;
3. свёртки: `дж`→`г`, `ж`→`г`, `й`→`и`, `ь`/`ъ` удаляются, двойные буквы
   сжимаются;
4. скелет — без гласных (`аеиоуыэюя`); если короче 3 символов, берётся полная
   форма.

Сходство = `max(rapidfuzz.fuzz.ratio(скелеты), ratio(полные формы)) / 100`.
Порог: `phonetic_threshold` для слов длиной ≥ `phonetic_short_length`, иначе
`phonetic_short_threshold`. Кандидаты сортируются по сходству, берутся
`hint_max`.

Проверка на эталонном наборе: `Сенжин` → скелет `снгн`, `OsEngine` → `осенгине`
→ скелет `снгн` (точное совпадение); `Всенж` → `вснг` (0.75); `Усеннджин` →
`уснгн` (0.89). Все три попадают в кандидаты `OsEngine`.

Склейка и разделение: `apply_glue` даёт кандидата с `glued=true`; дополнительно
подозрительное слово делится на два, если обе части известны `pymorphy3` или
лексикону и длина каждой ≥ 3. Кандидат «разделение» хранится как два слова через
пробел.

Случайный набор букв (нет гласных, серия согласных ≥ 5, нет кандидатов выше
порога): подсказок-слов не придумываем, остаются только «оставить» и
`[неразборчиво]`.

### Подсказки по смыслу

`prompts/normalize_pick.md` (новый файл, версионируется как остальные промпты).
Вход: слово, ±`context_utterances` реплик, нумерованный список кандидатов из
предыдущего шага, до `memory_neighbours` похожих по звучанию прошлых решений
оператора (`source='review'`). Выход по JSON-схеме:

```json
{
  "type": "object",
  "properties": {
    "verdict": {"type": "string", "enum": ["candidate", "keep", "unreadable"]},
    "candidate": {"type": "integer"},
    "reason": {"type": "string"}
  },
  "required": ["verdict", "candidate", "reason"]
}
```

Проверка ответа: при `verdict="candidate"` индекс обязан быть в диапазоне
списка; иначе выборка отбрасывается. Слово берётся из списка, поэтому «вернуть
слово вне списка» модель не может по построению. Если отброшены все выборки —
подсказок-слов нет, остаются «оставить»/`[неразборчиво]`.

Выборки: `hint_samples` вызовов, `temperature = hint_temperature`,
`seed = hint_seed + i`. Провайдер создаётся через `llm/`:
`provider_from_settings(settings, extra={"temperature": ..., "seed": ...})`,
`_params()` включает их в ключ кэша, поэтому каждая выборка кэшируется отдельно и
повторный прогон не тратит вызовы. Провайдер и модель не меняются.

Уверенность варианта = число выборок за него / общее число выборок. Подсказки
сортируются по уверенности, при равенстве — по порядку кандидатов.

### Автопроверки на уровне правки

Для каждой правки отдельно вызывается `run_checks_detailed` на паре
«текст до правки → текст после правки» с проверками: числа, отрицания, маркеры
неуверенности, имена (только из лексикона или списка кандидатов). Провал
отменяет только эту правку: остальные применяются, в `changes_json` пишется
`{"type": "rejected", "check": ...}` для отменённой.

### Команда `run`

- ворота «термины» (шаг 4) удаляются из пути по умолчанию; шаги `terms_table`,
  `quality_sample`, `review-terms` и применение `manual_edits` из `run`
  убираются (код команд остаётся, `manual_edits` включается
  `m7b.manual_edits_enabled: true`);
- после нормализации печатается `слов для оператора: N`;
- если `N > 0` и `m7b.wait_on_terms: true`, `run` останавливается **перед
  сегментацией** с сообщением `Помогите опознать N слов: <путь к файлу>`;
  флаг `--no-wait` продолжает с применением правил пустой ячейки;
- если L2 уже есть и незакрытых форм нет, нормализация не перезапускается
  (заморозка): `run` идёт дальше по стадиям;
- при наличии аннотаций L2 не пересобирается ни при каких условиях.

### Команда `apply-terms`

`qa-pipeline apply-terms [<код>] [--db]`.

1. Читает `terms_<проект>.xlsx`, лист «Нужна помощь».
2. Для каждой заполненной строки (и для пустых при
   `auto_apply_defaults: true`) пишет решение в `lexicon` с приоритетом
   `review > auto`; конфликт (форма уже привязана к другому канону) не
   применяется и помечается в `Пояснение`.
3. Детерминированно пересобирает L2: по сохранённому тексту `text_unit`
   применяет решения (замена, `keep`, `[неразборчиво]`), обновляет `position` и
   `changes_json`, пишет `decision` с `corrected_word`. Модель не вызывается,
   повторный запуск идемпотентен.
4. Если у интервью есть аннотации (`annotation` по его фрагментам) — команда
   ничего не меняет и печатает понятное сообщение о заморозке.
5. Без кода обрабатываются все интервью, у которых есть строки в таблице;
   интервью с аннотациями пропускаются с сообщением, остальные пересобираются.
6. Пишет строку журнала `run` (`stage='apply-terms'`, параметры: число решений,
   `lexicon_hash`) и удаляет применённые строки из «Нужна помощь», перенося их в
   «Применено само».

### Промпты

- `prompts/normalize.md`: только чистка речи, `asr_quality`, `uncertain_spans`.
  Подстановка `{lexicon}`, правила замены терминов и `new_terms` убираются;
  поле `new_terms` остаётся в схеме пустым для совместимости кэша и тестов.
- `prompts/normalize_pick.md`: новый, схема выше.

Место — подпись под блоком цитат (и/или в ограничениях отчёта). Реализация —
только после утверждения текста и места; до этого отчёт не меняется.

## Критерии приёмки (проверяемые, с командами)

Все проверки — на копии БД через `--db`, сеть не используется (провайдер
`stub` или скриптованная заглушка).

1. `uv run qa-pipeline normalize <код> --db <копия>` пишет L2, находит
   подозрительные слова, создаёт `data/exports/terms_<проект>.xlsx` с двумя
   листами; в «Нужна помощь» только новые формы, отсортированные по частоте.
2. Форма с решением в лексиконе (`review`) применяется кодом: счётчик вызовов
   модели для этой реплики равен нулю, в `changes_json` есть `decision`.
3. `Сенжин`, `Всенж`, `Усеннджин` дают `OsEngine` первым кандидатом
   (фонетический шаг), `glued=true` появляется для склеенной формы.
4. `apply-terms` после заполнения таблицы пишет решения в `lexicon`
   (`source='review'` для `=`,`?`,текста; `source='auto'` для пустой ячейки и
   автоподсказки), пересобирает L2 так, что в тексте стоит `OsEngine`, и
   оставляет `run`-строку.
5. Решение оператора не перезаписывается автозаменой: после повторного
   `apply-terms` с другой подсказкой в лексиконе остаётся `review`.
6. Конфликт (форма уже привязана к другому канону) не применяется: строка
   остаётся в таблице с пояснением «конфликт».
7. `apply-terms` при наличии аннотаций ничего не меняет: хеш БД до и после
   совпадает, печатается сообщение о заморозке.
8. Автопроверка отменяет только свою правку: при подмене числа одна правка
   отменена (`rejected`), остальные применены.
9. Модель не может вернуть слово вне списка: скриптованная заглушка с индексом
   `99` даёт отброшенную выборку; при всех отброшенных — только
   «оставить»/`[неразборчиво]`.
10. `run` останавливается перед сегментацией с `Помогите опознать N слов:
    <файл>`, фрагменты не создаются; `--no-wait` продолжает.
11. `uv run pytest -q`, `uv run ruff check .`, `uv run ruff format --check .`,
    `uv run mypy src` — зелёные.

запрещено.

## Риски и зависимости

- **Фонетика даёт ложные срабатывания** на коротких словах. Смягчение: строгий
  порог для коротких слов, лимит `hint_max`, обязательная проверка моделью,
  окончательное решение — за оператором или памятью.
- **Одна миграция** пересоздаёт `lexicon`; при ошибке в гарде данные не
  теряются, но миграция не применяется. Требуется разрешение оператора.
- **Таблица xlsx как интерфейс**: файл могут открыть в Excel, строки могут
  разойтись с БД. Смягчение: строки дописываются, а не перезаписываются;
  источник истины по незакрытым формам — БД (по `changes_json` и лексикону), а
  не файл.
- **Удаление лексикона из промпта** меняет текст L2 относительно текущих версий
  (модель больше не подставляет термины сама). Старые версии L2 сохраняются,
  заморозка не нарушается.
- **Стоимость подсказок**: `hint_samples × число новых форм`; кэш по `params`
  и лимит `llm.max_calls_per_run` ограничивают расход.
- Зависимости не добавляются; провайдер не меняется.

## Проверка по конституции (что из CONSTITUTION здесь критично)

- §4: SQL только в `src/qa/db/`; нормализация не пишет SQL, состояние приходит
  из репозиториев. Новые запросы — в `PipelineRepository`/`LexiconRepository`.
- §4/§6: схема БД меняется только миграцией; миграция показана и ждёт
  разрешения.
- LLM только через `llm/`, ответы по JSON-схеме, в тестах заглушка, сеть в
  тестах запрещена.
- Секреты и эндпоинты не попадают в код, промпты и логи; таблица и журнал
  содержат только формы и коды интервью, без имён и текста реплик сверх
  контекста, нужного оператору.
- L1 не меняется; оригинал и тайм-код остаются доступны.
- Тесты не ослабляются; отчёт — только подпись и только после согласования.
