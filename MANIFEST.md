# MANIFEST: анализатор интервью (тематический анализ)

Версия: 0.1. Положение в репозитории: `MANIFEST.md`. Меняется только по решению оператора.

## 1. Зачем это нужно
Интервью с пользователями, подключившими счёт в Финаме к ИИ, нужно превращать в структурированные выводы по двум узлам:
1. Понимание пользователем рисков.
2. Понимание и атрибуция ответственности.

Инструмент заменяет ручную сортировку расшифровок на воспроизводимый процесс тематического анализа: транскрипт, затем размеченные фрагменты, затем дерево тем с насыщением, затем отчёт.

## 2. Минимальное целевое видение (MVP)
Оператор кладёт расшифровку интервью в папку, запускает команду и получает:
- а) размеченные по кодбуку фрагменты с дословными цитатами, которые можно проверить и поправить;
- б) дашборд с текущим заполнением дерева тем (узлы, темы, коды-листья) и показателями насыщения;
- в) итоговый отчёт: графики и краткий текст модели, написанный только по посчитанным числам и реальным цитатам.

## 3. Метод
- Подход: тематический анализ, дедуктивная рамка (кодбук) плюс индуктивный слот для новых кодов.
- Человек в контуре: результат модели считается предложением. Статус «принято / исправлено / отклонено» ставит исследователь, и он важнее разметки модели.
- Насыщение: два показателя, по кодам и по смыслу. Смысловое насыщение в инструменте приблизительное и служит навигацией, а не доказательством.

## 4. Входы и источники истины
- Кодбук: приложение Б (Excel; структура зафиксирована и передана Финаму, не менять) и приложение А (правила разметки, Word).
- Гайд интервью: основной документ (Word). Идентификаторы вопросов (1, 7Т, 14Т-б и т. д.) постоянны.
- Транскрипты: текст интервью, имена заменены кодами респондентов, соцдем в обобщённом виде.
- Эталон по фактам Финама: отдельная таблица «Сверка фактов» (используется для оценки правильности понимания).

## 5. Выходы
- SQLite-база с интервью, фрагментами, аннотациями, ревью, прогонами.
- Дашборд (локальный).
- Отчёт (docx или HTML) с графиками.

## 6. Требования
- Воспроизводимость: каждый результат привязан к версии кодбука, модели и промпта.
- Прослеживаемость: каждая аннотация имеет дословную цитату, которая проверяется автоматически.
- Простота: SQLite, один процесс, локальный запуск. Усложнение допускается только по спецификации.
- Заменяемость: провайдер LLM, модель эмбеддингов и векторный индекс скрыты за интерфейсами.
- Малая выборка: инструмент не делает статистических выводов о различиях групп, только описательные сравнения.

## 7. Не входит в MVP
Многопользовательский режим, веб-сервер для коллег, автоматическая интерпретация без проверки человеком, презентации, обработка аудио (расшифровки приходят готовыми).

## 8. Критерии успеха MVP
1. Первый транскрипт проходит весь путь до дашборда без ручного вмешательства в код.
2. Ни одной аннотации с цитатой, которой нет в тексте.
3. Повторный прогон на тех же данных даёт тот же результат или явно объяснимые отличия (запись в `run`).
4. Дашборд показывает статус каждого листа дерева и кривые насыщения.
5. Отчёт собирается одной командой и не содержит чисел, которых нет в базе.

## 9. Открытые вопросы
- Провайдер LLM и модель эмбеддингов: оператор задаёт агенту отдельно (в конфигурации).
- Пороги статусов насыщения: подбираются после первых интервью.
- Темы дерева: предварительно по семьям кодов, уточняются на пилоте.
