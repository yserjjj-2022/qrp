# SPEC-M7: аддитивный протокол глоссария (лексикон)

Статус: approved (задание оператора 2026-11-11)
Связь с MANIFEST: §4 (рабочая книга — источник справочников), §6 (воспроизводимость, заменяемость), §8.3 (повторный прогон объясним)

## Цель

Убрать ретроактивность пополнения лексикона: новый термин не должен требовать
перепрогона всех уже нормализованных интервью. Стоимость обработки N-го
интервью не должна расти с размером корпуса.

## Контекст и входы

Сейчас `lexicon` — одна глобальная таблица без версии. Промпт нормализации
содержит весь лексикон (26 терминов, 824 символа из ~10 600 символов промпта),
а ключ кэша считается от промпта целиком. Поэтому добавление одного термина
меняет промпт всех реплик, обнуляет кэш интервью и требует `--new-version`,
то есть полного прохода. При N интервью и K ревизиях лексикона это N×K
прогонов.

Замеры на текущей базе: R01 — 131 вызов модели на версию L2; в очереди
`review-terms` 99 кандидатов (95 уникальных форм); на R02 детерминированный
проход находит 200 уникальных подозрительных слов.

## В рамках / вне рамок

В рамках:
- предварительный сбор терминов без модели (`--suspects-only`);
- правило заморозки: L2 не перезаписывается из-за изменения лексикона;
- фильтрация лексикона в промпте по реплике;
- хеш снимка лексикона в `run.params_json` и счётчик попаданий в кэш.

Вне рамок:
- изменение схемы БД и миграции (запрещено заданием оператора);
- версионирование лексикона в БД (`lexicon_version`);
- точечный пересчёт одного интервью;
- пересборка фрагментов при наличии аннотаций;
- выбор альтернативной модели и сравнение на сложных фразах (следующий шаг).

## Контракты данных

Схема БД не меняется. Меняется содержимое `run.params_json` для стадии
нормализации: добавляются ключи

| Ключ | Значение |
|---|---|
| `lexicon_hash` | sha256 от снимка лексикона: отсортированные строки `canonical\|variant1,variant2` |
| `lexicon_terms` | число терминов в снимке (уже есть) |
| `prompt_lexicon_filter` | включена ли фильтрация лексикона в промпте |
| `prompt_lexicon_threshold` | порог отбора терминов для промпта |

Промпт (`prompts/normalize.md`) не меняется. Фильтрация — только состав
подстановки `{lexicon}`.

## Поведение и правила

1. **Фильтр релевантности** (`relevant_lexicon`). В промпт реплики попадают
   только термины, релевантные её тексту:
   - любая форма термина (канон или вариант) точно встречается в тексте
     (сравнение по `_fold`, целыми словами);
   - либо любое подозрительное слово текста (`suspect_words`) имеет
     `fuzz.ratio` не ниже `m1b.prompt_lexicon_threshold` (по умолчанию 0.60)
     хотя бы с одной формой термина.
   Порог намеренно ниже порога замены (0.80): фильтр обязан быть шире, чтобы
   модель не теряла кандидатов. Пустой результат — допустим, подстановка
   `- (лексикон пуст)`.
2. **Область фильтра — только промпт.** Детерминированный проход и
   автопроверки (`check_latin`, `check_new_words`, `check_asr_fix`) работают с
   полным лексиконом: иначе фильтр ослабил бы проверки и изменил бы статусы.
3. **Заморозка.** `normalize <код>` без `--new-version` при уже записанной
   версии L2 ничего не пишет (как сейчас) и дополнительно сравнивает текущий
   `lexicon_hash` с хешем прогона, которым записана эта версия. При
   расхождении печатает предупреждение: L2 заморожен на прежнем снимке,
   изменения лексикона не применены, для применения нужен `--new-version`.
   Молчаливого перепрогона нет.
4. **Новая версия.** `--new-version` пишет следующую версию L2 с текущим
   снимком лексикона; предыдущие версии сохраняются.
5. **Предварительный сбор** (`--suspects-only`). Детерминированный проход по
   репликам интервью без вызовов модели: собирает `suspect_words`, пишет
   кандидатов в `new_term` (`status='proposed'`, `context_utterance_id`) и
   печатает уникальные формы с частотой. L2 не пишется, `run` не создаётся.
6. **Очередь ревью до нормализации.** `proposed_on_current_l2` сохраняет
   кандидатов интервью, у которого ещё нет ни одной версии L2: проверить
   форму по L2 нечем, но форма взята из L1 и реальна. Для интервью с L2
   поведение прежнее.
7. **Счётчик кэша.** `NormalizeStats.cached_calls` считает ответы, взятые из
   кэша (`LlmResult.cached`). Печатается в отчёте стадии.

## Критерии приёмки

1. `uv run qa-pipeline normalize R01 --suspects-only` печатает список
   уникальных подозрительных слов и не создаёт `run` и `text_unit`.
2. `uv run qa-pipeline normalize R01` после изменения лексикона печатает
   предупреждение о заморозке и не пишет новую версию.
3. `run.params_json` стадии нормализации содержит `lexicon_hash`,
   `prompt_lexicon_filter`, `prompt_lexicon_threshold`.
4. Повторный прогон с `--new-version` после добавления одного термина:
   число сетевых вызовов заметно меньше числа вызовов первого прогона
   (замер на копии БД, ожидание — большинство из кэша).
5. L2, полученный с фильтром, совпадает с L2 без фильтра на замере
   (допускаются отличия, объяснённые в отчёте).
6. `uv run pytest -q`, `uv run ruff check .`, `uv run ruff format --check .`,
   `uv run mypy src` проходят.

## Тесты

- `relevant_lexicon`: точное вхождение, fuzzy-кандидат, отсутствие
  релевантных терминов, многословный термин.
- `lexicon_snapshot_hash`: стабильность при разном порядке, изменение при
  добавлении варианта.
- `normalize_interview`: `cached_calls`, `lexicon_hash` в `run`, предупреждение
  о заморозке, `--new-version` пишет новую версию.
- `collect_suspects`: кандидаты в `new_term`, отсутствие `run`/`text_unit`.
- `proposed_on_current_l2`: кандидат интервью без L2 остаётся в очереди.
- CLI: `--suspects-only` не создаёт версию L2.

## Риски и зависимости

- Фильтр может сузить промпт сильнее, чем нужно, и изменить разметку.
  Снижение: порог 0.60, замер совпадения L2 на копии, отключаемый флаг
  `m1b.prompt_lexicon_filter`.
- Замер требует реальных вызовов модели на копии БД; текущий корпус не
  затрагивается.
- Заморозка не блокирует, а предупреждает: оператор может проигнорировать
  предупреждение и остаться на старом снимке.

## Проверка по конституции

§4: схема не меняется, миграций нет, запросы только через репозитории.
§6: L2 не перезаписывается без явной команды; прогон фиксирует снимок
лексикона. §7: вызовы только через `llm/`, кэш по ключу. §9: тесты и
проверки. §12: изменение схемы не выполняется без отдельного разрешения.

## Открытые вопросы

1. Достаточно ли порога 0.60 или нужен замер на нескольких интервью.
2. Нужен ли точечный пересчёт одного интервью (вариант C) — отложено до
   первых 3–5 интервью.
