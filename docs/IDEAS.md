# IDEAS: идеи для развития

Записываем идеи, которые не входят в текущую спецификацию.

## Расшифровка и нормализация

- **Повторная расшифровка другим ASR-движком (например, Nemotron).** Машинная расшифровка
  местами искажает термины и содержит нечитаемые места; второй движок позволит сравнить
  варианты и выбрать более надёжный фрагмент. В схеме уже есть
  `interview.transcript_source`, поэтому повторная расшифровка не потребует смены модели
  данных. Вне M1.
- **Сравнение версий L2 между движками.** Если появится вторая расшифровка, полезна
  метрика расхождения L1/L2 по репликам, чтобы выбирать движок по данным, а не на глаз.
- **Золотой набор для L2.** 30-50 реплик первого транскрипта с ручной нормализацией:
  даёт метрику «доля принятых без правок» и позволяет проверить, не срезает ли проход
  смысл. Требует ручной работы оператора, поэтому вынесено за рамки текущей задачи.
- **Выборочная проверка ревьюером.** Просмотр всех единиц с флагами плюс случайной доли
  (порог `m1b.review_sample_share`) в интерфейсе сравнения L1 и L2 рядом. Нужны статусы
  «принято / исправлено / отклонено» и замораживание версии (`approved`).
- **Проверка отношения длин L2/L1.** Ориентир 0,6-1,1 из SPEC: ловит и потерю смысла,
  и «переписывание» ответа. Пороги в конфиге уже есть, но метрика не считается, пока
  нет золотого набора для калибровки.
- **Проверка новых смысловых слов по леммам.** Автопроверка 5 SPEC требует `pymorphy3`;
  сейчас её заменяет консервативная проверка названий. Без лемматизации нельзя отличить
  законную словоформу от придуманного слова.
- **Пополнение лексикона из прогонов.** Сейчас `new_term` копит кандидатов, а решение
  принимает `review-terms`. Полезно показывать в отчёте, сколько единиц отклонено
  именно проверкой названий: это прямой сигнал, что лексикон неполон.

## Разметка M2

- **Две аннотации вместо одной для кодов A3/4.** Код A3/4 в текущем кодбуке не различает
  подвиды ответственности, поэтому предлагается ставить по нему две аннотации с признаком
  «не различает»: расхождение внутри кода видно в отчёте и не теряется при агрегации.
  Требует уточнения на пилоте, в M1 не входит.
- **Общий признак «код не различает подтипы».** Механизм вместо отдельного правила для
  A3/4: поле у кода, помечающее, что код агрегирует несколько смыслов.
