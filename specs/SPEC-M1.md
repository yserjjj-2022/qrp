# SPEC-M1: от транскрипта к фрагментам (M1a, M1b, M1c)

Статус: approved (версия 4, объединяет прежние SPEC-M1 и SPEC-M1b)
Связь с MANIFEST: разделы 2(а), 3, 4, 6.
Зависит от: SPEC-M0 (выполнен и принят).

Спецификация состоит из трёх этапов: M1a, M1b, M1c. После каждого этапа агент останавливается, отчитывается по шаблону и ждёт слова «принято» от оператора. К следующему этапу не переходить без него.

Порядок: M1a (разбор и сборка реплик) -> M1b (нормализация, слой L2) -> M1c (привязка к вопросам и сегментация по L2).

## Цель
Превратить текстовую расшифровку интервью в проверяемые фрагменты текста с привязкой к вопросам гайда, пригодные для кодирования (M2).

## Формат входа (по первому транскрипту)
- Текстовый файл UTF-8 (возможна BOM). Первая строка: заголовок с названием и датой. Далее записи `ЧЧ:ММ:СС<TAB>Метка говорящего<TAB>Текст`, одна запись на строку (218 записей в первом транскрипте).
- Метки: полные имена; три метки: интервьюер, респондент, наблюдатель (одна короткая реплика в конце).
- Временная метка: начало реплики, точность до секунды; не убывает, совпадающие секунды возможны.
- Много односложных реплик интервьюера («Угу.» и подобные) разрезают длинный ответ респондента на несколько записей.
- Расшифровка машинная: искажения терминов и отдельные нечитаемые места. Исходный текст не правится.

## Входные данные для интервью
Файл `interview.yaml` (в `data/`, не в репозитории): `interview_id`, `respondent_code` (R01...), `group` (ТОРГ / не торгующие, по данным Финама), `roles` (метка говорящего -> INTERVIEWER | RESPONDENT | OBSERVER), `names_to_codes` (имена, встречающиеся в тексте, -> коды), `date`, `transcript_source`. Роли не определяются автоматически.

Уточнение (2026-11-05, реализовано в M1a): `interview.yaml` больше не требуется.
- Код респондента берётся из имени файла (`R01.txt` -> `R01`); имя файла без кода — ошибка.
- Дата берётся из заголовка транскрипта (ISO или `ДД.ММ.ГГГГ`), иначе из листа «Интервью».
- Группа берётся из листа «Интервью» или параметра `--group`.
- Роли предлагаются по числу слов (больше слов — RESPONDENT, второй — INTERVIEWER, остальные — OBSERVER) и подтверждаются оператором в `init-interview`. Если роли уже есть в БД (лист «Интервью» / прошлый запуск), они не запрашиваются повторно.
- Таблица «имя -> код» хранится вне репозитория; путь задаёт `NAMES_MAP_PATH`, при отсутствии файла создаётся заготовка.
- `interview.yaml` поддерживается только как совместимость (`load-transcript --meta`).

## Рабочая книга как источник справочников (уточнение 2026-11-05)

Кодбук, дерево тем и необязательные справочники загружаются из рабочей книги проекта
(`load-codebook` и `load-project`); отдельные YAML-файлы `schema/*.yaml` для этих данных
не используются. Схема «лист -> колонка -> тип» задана в `config.yaml`.

1. **Группы.** Значения `interview.group` и `question.group` приводятся к каноническим
   (`Все`, `ТОРГ`, `Не торгующие`) по секции `groups` в `config.yaml`; сравнение без учёта
   регистра и с нормализацией пробелов/подчёркиваний. Неизвестное значение не ошибка:
   сохраняется как есть, в отчёт выводится предупреждение. Жёсткие списки групп в коде
   отсутствуют.
2. **Вопросы группы ТОРГ не обязательны.** Книга без вопросов «ТОРГ» загружается
   `load-codebook` и `load-project`, транскрипты респондентов группы «Не торгующие»
   проходят `init-interview` и `load-transcript` без ошибок. Состав гайда не проверяется
   по ожидаемому списку: контролируются только перекрёстные ссылки между листами.
3. **Строгие колонки.** Колонка «коды (через ;)» листа «Темы» помечена `strict: true`:
   нераспознанный элемент (например, опечатка `R 1`) вызывает `WorkbookError` с именем
   листа, номером строки, именем колонки и списком нераспознанных значений. Пометки
   «пусто» (`—`, `–`, `-`) значением не считаются.
4. **Пустые темы.** Пустая тема (нет кодов), узел без тем и строка без узла — заметки
   в отчёте, а не ошибка: загрузка кодбука продолжается, дерево достраивает оператор.
   Дерево строится по листу «Темы»; если лист пуст или отсутствует — по семьям кодов
   с маппингом `workbook.family_nodes`.
5. **Статусы лексикона.** Статус из листа «Лексикон» приводится к `proposed` / `approved` /
   `rejected` по секции `lexicon_status_map`; пустой статус — `proposed`, неизвестный —
   `proposed` плюс предупреждение в отчёт. Сравнение с решениями `review-terms` идёт
   по приведённым значениям, чтобы расхождение не считалось ложным.
6. **Оценка понимания.** Вопросы 19 и 20 и блок 8 в текущей версии гайда не используются
   для оценки понимания: эта оценка не реализована и в M1 не входит.

## Слои текста
- L0: исходный файл, вне репозитория.
- L1: псевдонимизированный дословный текст (`utterance.text`). Меняются только метки говорящих и имена.
- L2: нормализованный текст (`text_unit.text`). По нему идут привязка к вопросам, сегментация, кодирование, эмбеддинги, поиск, цитаты в дашборде и отчёте.

## M1a. Разбор и сборка реплик

1. Парсер формата: запись `turn` (interview_id, line_no, start_sec, speaker_role, text). Строка не по формату вызывает ошибку с номером строки; пропуск молча запрещён.
2. Псевдонимизация: метки говорящих заменяются ролями и кодом респондента; имена в тексте заменяются кодами по `names_to_codes`. Текст в БД это L1.
3. Фильтр шаблонов (телефоны, e-mail, длинные числа, похожие на номера счетов): совпадения помечаются `pii_flag`.
   Уточнение (2026-11-05): `pii_flag` только помечает запись для ручной проверки и не блокирует ни загрузку, ни отправку в модель. Шаблон длинных чисел срабатывает и на денежных суммах («100 000 рублей») — это ожидаемо, такие записи разбирает оператор.
4. Сборка реплик (`utterance`): подряд идущие записи одного говорящего, разделённые только короткими вставками другого говорящего (до 3 слов из настраиваемого списка вроде «угу», «ага», «да», «так»), объединяются в одну реплику; ссылки на записи (`turn_ids`) сохраняются; вставки помечаются `is_backchannel`, не удаляются.

Данные (миграция 0002): `turn`: id, interview_id, line_no, start_sec, speaker_role, text, pii_flag. `utterance`: id, interview_id, speaker_role, text, turn_ids, is_backchannel. В `interview`: respondent_code, group, transcript_source.

Критерии приёмки M1a:
1. Синтетический транскрипт в описанном формате разбирается; число записей, ролей и порядок совпадают с ожидаемыми.
2. Тест `real_transcript` (только при заданной переменной окружения с путём к реальному файлу): распознано 218 записей, ролей три, временные метки не убывают, исходных меток говорящих и имён из `names_to_codes` в сохранённом тексте нет.
   Уточнение (2026-11-06): критерий касается текста L1 и L2 — в них меток нет. В самой БД метки допустимы как служебные данные (`turn.speaker_label`, `interview_speaker.speaker_label`) и не попадают в логи, отчёты, промпты и внешние модели (CONSTITUTION §5).
3. Строка не по формату вызывает ошибку с номером строки.
4. Повторная загрузка того же интервью не создаёт дублей. Уточнение (2026-11-05): признак «уже загружено» — наличие записей `turn`, а не строки `interview`. Если строка создана раньше (`init-interview` или лист «Интервью») и записей нет, `load-transcript` не вставляет новую строку, а дополняет существующую: пишет заголовок с псевдонимизацией, дату, группу (через `normalize_group`), `transcript_source` и роли, после чего загружает записи и реплики. Поэтому порядок `init-interview` -> `load-transcript` на одной БД работает без удаления данных.
5. Сборка реплик не теряет текст: объединение текстов записей реплики (без вставок) совпадает с текстом реплики.

Остановка: отчёт, ожидание «принято».

## M1b. Лёгкая нормализация (слой L2)

Цель: из L1 создать читаемый L2, пригодный для цитирования, поиска и кодирования. L0 и L1 не меняются. Главное требование: сохранить сигналы неуверенности и обдумывания; удаляется шум речи и расшифровки, а не смысловые оговорки. Единица нормализации: реплика (связь L2 с L1 один к одному).

### Удалять
1. Звуки-паразиты и междометия без смысла («э-э», «м-м»).
2. Механическое заикание: подряд идущий повтор служебного слова, предлога, союза, частицы или местоимения без смысловой нагрузки («и и», «они, они, они»), оборванное слово, ложный старт, заменённый исправлением.
3. Явные паразиты, не выполняющие роль оговорки («вот», «короче», «это самое»), если их плотность высока (порог в конфиге).
4. Дублирование из-за наложения речи или артефактов расшифровки.

### Сохранять
1. Любые выражения неуверенности и осторожности: «не знаю», «не уверен», «наверное», «возможно», «кажется», «по-моему», «вроде», «не помню», «может быть», «скорее всего», «сложно сказать», «я не задумывался» и подобные. Список хранится в листе «Маркеры_неуверенности» рабочей книги и пополняется оператором; если листа нет, применяются умолчания из `config.yaml` (`workbook.defaults.uncertainty_markers`).
2. Повторы-обдумывание: повтор смысловой фразы или оценочного слова («не знаю, не знаю»), возврат к мысли, самопоправка, меняющая смысл, повтор для усиления.
3. Отрицания, числа, названия, условия, модальность.
4. Сомнение, выраженное словами («как бы», «типа», «вроде»), если смягчает конкретное утверждение; удалять только очевидный тик.
5. Логические связки и противоречия. Нельзя делать ответ связнее, чем он есть.

### Править осторожно (с записью в журнал изменений)
1. Термины и названия по лексикону — лист «Лексикон» рабочей книги (каноническая форма, варианты ASR-искажений, статус утверждения оператором). Решения `review-terms` приоритетнее листа.
2. Очевидные ошибки распознавания по контексту и лексикону.
3. Порядок слов и согласование, только если смысл однозначен. Сложные перестройки запрещены.
4. Пунктуация и деление на предложения.

### Не делать
1. Не добавлять сведений, которых нет в L1.
2. Не раскрывать местоимения.
3. Не гадать про незнакомые термины: вариант идёт в `new_term` на утверждение оператором, в тексте остаётся как есть.
4. Не восстанавливать совершенно искажённые места: ставится `[неразборчиво]`, `asr_quality=garbled`.
5. Не «улучшать стиль».

Если нельзя уверенно отличить заикание от обдумывания, повтор сохраняется, в журнал пишется `repeat_unclear`. Консервативное значение по умолчанию: оставить.

Реплики интервьюера нормализуются только детерминированно (термины по лексикону, звуки-паразиты, пунктуация), без модели: точная формулировка нужна для признака «спонтанно / по подсказке».

Метаданные вместо удалённого шума: `fillers_removed`, `stutter_removed`, `repeat_unclear` (счётчики) сохраняются в `text_unit`.

### Порядок обработки
1. Детерминированный проход: замены по лексикону, удаление звуков, пробелы, очевидные механические повторы служебных слов.
2. Проход модели по реплике респондента (через `llm/`, JSON по схеме, температура 0, кэш). Вход: реплика L1, предшествующая реплика интервьюера, лексикон, маркеры неуверенности, 2-3 образца из `prompts/normalize_examples.md`. Выход: `normalized_text`, `changes[]` (term, filler, stutter, order, punctuation, garbled), `uncertain_spans[]`, `new_terms[]`, `asr_quality` (ok | doubtful | garbled).
3. Автоматические проверки (ниже). Не прошла: статус `rejected`, в L2 результат только детерминированного прохода.
4. Выборочная проверка человеком: все единицы с флагами плюс случайная доля (по умолчанию 10 %), сравнение L1 и L2 рядом. Статусы: принято / исправлено / отклонено.
5. Замораживание: после проверки версия L2 интервью получает статус `approved`. Любое изменение создаёт новую версию. Аннотации хранят версию текста.

### Автоматические проверки
1. Все числа из L1 есть в L2.
2. Все отрицания («не», «нет», «ни», «без») сохранены.
3. Все вхождения маркеров неуверенности из L1 есть в L2 (100 %, без исключений).
4. Все названия и латиница сохранены в исходном или каноническом виде.
5. В L2 нет новых смысловых слов, которых нет в L1 или лексиконе (по леммам; см. открытые вопросы).
6. Отношение длины L2 к L1 в заданных границах (ориентир 0,6-1,1, параметр).
7. Идемпотентность: повторный запуск с теми же входами даёт тот же результат или читает кэш.

Данные (миграция 0005, в SPEC ранее указывалась 0003): `text_unit`: id, utterance_id, version, text, status (proposed|approved|rejected), asr_quality, changes_json, uncertain_spans_json, fillers_removed, stutter_removed, repeat_unclear, run_id, review_status, reviewed_at. `lexicon`: canonical, variants_json, definition, status, source. `new_term`: id, interview_id, surface_form, context_utterance_id, status.

Критерии приёмки M1b:
1. Синтетические примеры (`tests/fixtures/`): «Они, они, они на подстраховке» -> «Они на подстраховке»; «Не знаю, не знаю, вопрос, наверное, в простоте» без изменений; «Я, ну, не помню, чтобы он ошибался» -> «Я не помню, чтобы он ошибался»; «Подключил эсипи Финам» -> «Подключил MCP Финам» при термине в лексиконе; незнакомый термин остаётся как есть и попадает в `new_term`; искажённый фрагмент получает `[неразборчиво]` и `asr_quality=garbled`.
2. Реплики интервьюера не проходят через модель.
3. Автопроверки 1-4 обнаруживают намеренно испорченный вывод модели (тест с подмененной заглушкой) и отклоняют единицу.
4. Повторный запуск идемпотентен; новая версия L2 создаётся только по команде оператора.
5. Тест `real_transcript_golden` (по переменной окружения; файл с ручной разметкой оператора лежит в `data/`, не в репозитории): сохранность маркеров неуверенности 100 %, чисел и отрицаний 100 %; отдельно печатается доля единиц, принятых без исправлений при ручной проверке (метрика, не порог).
6. LLM в тестах заменён заглушкой, сети нет.

Остановка: отчёт, ожидание золотого набора и «принято» от оператора. Для приёмки оператор готовит 30-50 реплик первого транскрипта с ручной нормализацией (агент реальный транскрипт в репозитории не хранит).

Уточнение (2026-11-06, урезанный объём M1b по решению оператора):
- Реализованы: детерминированный проход, проход модели по репликам респондента, автопроверки 1-4 и 7 (идемпотентность), запись `text_unit` и `run`.
- Таблица `text_unit` создаётся миграцией `0005`, а не `0003`: номер `0003` занят рабочей книгой, `0004` — меткой говорящего в `turn`.
- `text_unit.status` принимает только `proposed` и `rejected`; `approved` и замораживание версии не реализованы.
- Ручная проверка (шаг 4 порядка обработки), золотой набор и метрика доли принятых без правок не реализованы; `review_status` и `reviewed_at` не заполняются.
- Автопроверка 5 (новые смысловые слова по леммам) не реализована: `pymorphy3` остаётся одобренной зависимостью на будущее. Её частично заменяет консервативная проверка 4: слово с заглавной буквы или латиница, которых нет во входе и в лексиконе, отклоняют единицу.
- Автопроверка 6 (отношение длин) не реализована; пороги остаются в `config.yaml` для калибровки на золотом наборе.
- Порог отправки в модель — `m1b.min_words_for_model` (по умолчанию 4 слова). Реплики интервьюера, наблюдателя и бэкканалы в модель не отправляются.
- `run.code_version` — версия пакета плюс короткий хеш коммита (`git rev-parse --short HEAD`), при отсутствии git — только версия.

## M1c. Привязка к вопросам и сегментация (по L2)

1. Привязка к вопросам: для каждой реплики интервьюера определяется, основной ли это вопрос гайда (с id вопроса), уточнение (`is_probe`) или вне гайда. Каждая реплика респондента получает `question_id` вопроса, на который отвечает, и `prior_interviewer_turn_id`. Используются сходство с формулировками вопросов (эмбеддинги) и проверка моделью. Порядок вопросов в интервью может отличаться от гайда; реплики вне гайда допустимы.
2. Сегментация: реплика респондента (L2) делится на смысловые фрагменты (одна мысль, обычно 1-4 предложения). Границы предлагает модель; код проверяет, что каждый фрагмент дословно равен срезу текста L2 и что фрагменты одной реплики не пересекаются.
3. Для привязки по возможности передавать модели весь транскрипт L2 с разметкой реплик (интервью целиком помещается в контекст), а не отдельные реплики.

Данные (миграция 0006; в SPEC ранее указывалась 0005, занятая слоем L2): в `utterance` заполняются question_id (nullable), is_probe, prior_interviewer_turn_id. `fragment`: id, utterance_id, text_unit_id, start, end, text, question_id, prior_interviewer_turn_id, asr_quality.

Критерии приёмки M1c:
1. Для каждого фрагмента `text` равен срезу текста L2 по `start:end`; фрагменты одной реплики не пересекаются.
2. Реплика вне гайда получает `question_id = NULL`, а не ближайший вопрос.
3. Тест `real_transcript` (по переменной окружения): распределение реплик по вопросам выводится в отчёт для ручной проверки оператором.
4. LLM в тестах заменён заглушкой, сети нет.

Остановка: отчёт, ожидание «принято».

## Риски
- Машинная расшифровка местами нечитаема; решение: `asr_quality`, нечитаемые места не участвуют в оценке понимания.
- Интервьюер иногда сам называет категории или сообщает факты; `prior_interviewer_turn_id` нужен для признака «спонтанно / по подсказке».
